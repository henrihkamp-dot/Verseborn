# Selector portrait recovery

Live clean-browser verification showed the reported Rift enemy and party portraits load successfully (HTTP 200 WebP). The failure was not reproduced in that fresh session; do not claim a proven missing-file root cause.

Version selector portrait URLs and the three selector modules to avoid stale failed responses. Create enemy overview and selected formation images with a scoped assignment helper, eager/high priority and direct DOM source attributes; these newly created images do not enter the shared world-art queue. A capture handler applies only to those registered images and retries the same character portrait from the existing GitHub asset mirror. No placeholder, shared portrait registry, battle sprite, save or animation edits.
